# Coding Pitfalls

- `@pierre/diffs` `File` can collapse under dev React StrictMode with a cold grammar because its first instance leaves an unfinished shadow-DOM `<pre>`, while the remounted instance treats any `<pre>` as hydrated and skips the render completion callback; keep the `FILE_OPTIONS.onPostRender` unmount cleanup in `apps/syokan/src/catalogs/Code/index.tsx`, removing only a `<pre>` without `[data-code]`, and re-test a cold-grammar first mount in a real dev browser after pierre upgrades because `<pre>` and `[data-code]` are internal DOM details.
- In `apps/syokan/server/fileSource.ts`, watch the file and re-arm after `rename` on macOS because Bun directory watches miss descendant content changes; on Linux watch the parent without basename filtering because file watches miss inode swaps and coalesced atomic-save events may report only the temporary filename.
- Keep `apps/syokan/bunfig.toml` as a symlink to `../../bunfig.toml`: Bun reads `bunfig.toml` only from the current working directory, so the package-scoped dev process otherwise misses `bun-plugin-tailwind` and serves CSS without utilities.
- If an edited frontend module does not appear in the Bun HTML-import dev server even though source and typecheck are current, restart the dev server; touching the file or reloading the browser may retain a stale module bundle, so source-versus-DOM mismatch is the useful signal.
- Do not embed literal NUL bytes in source files, including as string delimiters: `apps/syokan/server/fileSource.ts` rejects the file as `not_text`, which also prevents `TreeDoc` reads and `Probe.search_count`; compare structured identity fields separately instead of joining them with a sentinel.
- A dev-server process from a stale/different checkout (e.g. another git worktree of this repo) can keep squatting on the lazy-spawn port (5173/5273) serving a broken zero-byte HTML bundle, and `syokan stop` cannot kill it because it only tracks pids it recorded in `~/.local/state/syokan/server-<port>.json`, not processes started another way; diagnose with `lsof -ti :<port>` then `lsof -p <pid> -a -d cwd` to confirm the offending process's working directory, kill it directly, and `syokan` will lazy-spawn a fresh working server on the freed port.
- `bun run dev` needs an interactive terminal and cannot run from a sandboxed/non-interactive shell: `apps/syokan`'s dev script requires the portless proxy already running (`sudo portless proxy start --https` needs a TTY) and `@syokan/share:dev` (wrangler) writes to `~/Library/Preferences/.wrangler/`, which a sandbox blocks; bypass both by starting the syokan server directly, e.g. `cd apps/syokan && XDG_CONFIG_HOME=$PWD/../../.syokan-dev/config XDG_DATA_HOME=$PWD/../../.syokan-dev/data XDG_STATE_HOME=$PWD/../../.syokan-dev/state PORT=5273 bun --hot server/index.ts`.
