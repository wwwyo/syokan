# Coding Pitfalls

- TanStack Router's `scrollRestoration` keys positions by history entry by default, not by route/pathname: navigating A → B → A creates a new entry for the second visit to A, so its scroll position does not carry over even though it's the same URL. To restore scroll per-route (e.g. per-snapshot in `apps/syokan/src/router.tsx`), pass `getScrollRestorationKey` returning the pathname; then history entries sharing a pathname (via router `Link`/back-forward) share one restoration slot, and in-view anchor hashes (written via `history.replaceState`, not router navigation) must stay out of that key or an anchor jump lands in a separate slot that never restores. The actual storage (in-memory cache + `sessionStorage` flush on `pagehide`, key `tsr-scroll-restoration-v1_3`) lives entirely inside `@tanstack/router-core`; syokan only supplies the key function.

- `@pierre/diffs` `File` can collapse under dev React StrictMode with a cold grammar because its first instance leaves an unfinished shadow-DOM `<pre>`, while the remounted instance treats any `<pre>` as hydrated and skips the render completion callback; keep the `FILE_OPTIONS.onPostRender` unmount cleanup in `apps/syokan/src/catalogs/Code/index.tsx`, removing only a `<pre>` without `[data-code]`, and re-test a cold-grammar first mount in a real dev browser after pierre upgrades because `<pre>` and `[data-code]` are internal DOM details.
- Keep `apps/syokan/bunfig.toml` as a symlink to `../../bunfig.toml`: Bun reads `bunfig.toml` only from the current working directory, so the package-scoped dev process otherwise misses `bun-plugin-tailwind` and serves CSS without utilities.
- If an edited frontend module does not appear in the Bun HTML-import dev server even though source and typecheck are current, restart the dev server; touching the file or reloading the browser may retain a stale module bundle, so source-versus-DOM mismatch is the useful signal.
- Do not embed literal NUL bytes in source files, including as string delimiters: `apps/syokan/server/readFile.ts` rejects the file as `not_text`, which blocks `Probe.search_count` hits when a probed file carries one; compare structured identity fields separately instead of joining them with a sentinel.
- `bun run dev` needs an interactive terminal and cannot run from a sandboxed/non-interactive shell: `apps/syokan`'s dev script requires the portless proxy already running (`sudo portless proxy start --https` needs a TTY) and `@syokan/share:dev` (wrangler) writes to `~/Library/Preferences/.wrangler/`, which a sandbox blocks; bypass both by starting the syokan server directly, e.g. `cd apps/syokan && XDG_CONFIG_HOME=$PWD/../../.syokan-dev/config XDG_DATA_HOME=$PWD/../../.syokan-dev/data XDG_STATE_HOME=$PWD/../../.syokan-dev/state PORT=5873 bun --hot server/index.ts`.
- A `Mermaid` node that silently falls back to raw-code rendering, with no visible error, is usually a parse failure from a reserved word used as a bare node ID (e.g. `call`, which mermaid's flowchart grammar reserves for `click X call cb()`); bisect by posting single-line probe snapshots to isolate the failing statement, then rename the ID. `apps/syokan/src/catalogs/Mermaid/index.tsx` now surfaces the caught parse message in the fallback UI, but `mermaidPropsSchema` still does no syntax validation at POST time (parsing needs a DOM, which isn't available server-side), so the posting LLM still learns nothing from the POST response — only a human looking at the rendered view sees the reason.
- Size `Mermaid`'s rendered height with a fixed `rem` (e.g. `max-h-[32rem]`) plus `overflow-auto`, not `dvh`: in headless/measurement environments (e.g. preview embeds) the viewport can report 0 height, and a `dvh`-based cap collapses the diagram to zero height there.
- Catalog component tests in this repo render via `renderToString` (SSR), so `useEffect`-driven state (e.g. `Mermaid`'s async render/error path) never runs; a test can only cover the pure logic factored out of the effect (e.g. an exported `errorMessage()` helper), not the resulting DOM. Testing the effect-driven DOM itself would need a real DOM test environment, which isn't set up here.
- Mermaid's flowchart grammar gets more permissive across versions (Storybook's `ParseError` story input silently stopped throwing after a mermaid bump — `???broken???` used to fail, now parses as a label). A story/test that documents an error path by example must be re-verified after any mermaid version bump, not assumed to still throw.
- Any catalog component that imports `Render.tsx` (to render a subtree — the removed `TreeDoc` did this) creates a cycle `catalogs/index.ts → <Component> → Render.tsx → catalogs/index.ts`, and whichever module the bundler enters first (a Storybook story, a test) hits `Cannot access '<schema>' before initialization`: `catalogs/index.ts`'s top-level `entries` array reads every component's exported `const ...propsSchema` eagerly, but `const` is in the TDZ mid-cycle while a `function` declaration is hoisted. Fix by moving the schema to a leaf module (as `TreeDoc/schema.ts` was) that imports nothing from the cycle, and keep the component itself as a `function` declaration, not `const Component = (...) => ...` — that conversion silently reintroduces the same TDZ crash for the whole render tree. A `Bun.spawnSync` test that imports the component *first* in a fresh subprocess is the only way to catch a regression; importing it from within the same test file can't reproduce the ordering because the registry module is already cached.
- In `apps/syokan/src/catalogs/Graph/layout.ts`, dagre treats compound-cluster border nodes as dummies and spaces them by `edgesep` (default 20), not `nodesep`, so any padding added to group boxes after `dagre.layout` must stay below both `nodesep` and `edgesep` (and `ranksep` on the rank axis) or two groups sharing a rank overlap; the layout tests assert non-overlap on the exact posted overview shape because a synthetic two-group case passed while the real one overlapped.
- When fixing review comments by editing files, re-check the file's final `git diff` right before committing: this repo runs review automation that can write the same file mid-task — `.github/pullfrog.config.sh` sets `address-reviews.enabled` + `push=enabled`, and a concurrent local session can edit the checkout too. Observed on PR #109: a manual `|| true` fix in `orca.yaml` was silently overwritten between edit and commit by a broken variant (`""$HOME""` pseudo-quoting that doesn't actually quote, `;` replacing the group guard) with no pushed automation commit observed on the PR — i.e. likely a local working-tree write (a force-push or amend rewriting history can't be ruled out).
