# PRD: demo-video

## Problem

syokan の価値提案「LLM が JSON の呪文を唱えると、リッチな UI が召喚される」は、README のテキストを読み込まないと伝わらない。
dev ツールの拡散は X と README 冒頭の数秒で起きるが、syokan にはその数秒で価値を伝える視覚素材が存在しない。
インストール経路 (one-command-install PRD) を整えても、試したいと思わせる入口がなければ流入は生まれない。

## Overview

Claude Code への依頼から view が開くまでを収めた短い mp4 デモ動画を1本制作し、README 冒頭と X 投稿に使う。
LP は作らず、GitHub リポジトリを着地点とする。

### Goals

- README を開いた人が、動画だけで「Claude Code に頼む → UI が現れる」という体験を理解できる
- X にそのまま投稿できる形式とサイズの動画が手に入る
- 動画の最後で、視聴者が次に取る行動 (インストールコマンド) に接続する

### Non-Goals

- LP (ランディングページ) は作らない (着地点は GitHub リポジトリとする)
- ナレーションや字幕つきの長尺スクリーンキャストは作らない
- GIF は作らない (mp4 のほうが容量あたりの画質が高く、README と X の両方に埋め込める)
- 多言語版は作らない (プロダクトの英語既定に合わせ、英語1本とする)

## User Stories

### US-001: README 訪問者が数十秒で価値を理解する

**説明:** X やリンク経由で README に来た開発者が、文章を読み込む前に syokan が何かを理解したい。なぜなら初見の判断は数十秒で下され、そこで伝わらなければ離脱するからだ。

**受け入れ条件:**
- [ ] README 冒頭で動画がインラインで再生できる
- [ ] 動画は「Claude Code への依頼 → skill が snapshot を POST → ブラウザに view が現れる」の一連が1カットで追える
- [ ] 事前知識のない開発者3名に動画だけを見せ、2名以上が「LLM に頼むと UI が出る道具」だと説明できる

### US-002: X で見かけた人がリポジトリに流入する

**説明:** メンテナ (wwwyo) が、X に動画つきでプロダクトを投稿したい。なぜなら dev ツールの初期流入は SNS 上のデモ動画が起点になることが多く、テキスト投稿では埋もれるからだ。

**受け入れ条件:**
- [ ] 動画が X のインライン再生要件 (形式、長さ、ファイルサイズ) を満たす
- [ ] スマートフォンの画面サイズでも、ターミナルの文字と view の内容が判読できる
- [ ] 動画の末尾または投稿文で、リポジトリ URL とインストールコマンドに誘導する

### US-003: メンテナが製品の変化に合わせて撮り直せる

**説明:** メンテナが、UI や skill の挙動が変わったときに同じ筋書きで動画を撮り直したい。なぜならデモが実物と乖離すると、視聴者が試した瞬間に信頼を失うからだ。

**受け入れ条件:**
- [ ] デモの筋書き (依頼文、使うデータ、見せる view) が再現可能な形で記録されている
- [ ] 記録された筋書きに従えば、同等の動画を再制作できる

## Constraints

- 題材は「Claude Code からの召喚」とする (`syokan notes.md` のような CLI 単体の絵ではなく、LLM が唱える瞬間を見せる)
- 動画は視聴者がその時点で再現できる経路のみを見せるため、公開は one-command-install PRD と claude-code-plugin PRD の完了後とする
- デモに使うデータは、実在の作業を模した具体性を持つ合成の fixture をリポジトリに置いて使い、秘密情報や第三者の情報を含めない (ダミーだと分かる Lorem ipsum 的な中身は訴求を弱める)
- 製品コピーは英語既定であるため、デモ内の依頼文と view の内容も英語とする
- README への動画埋め込みは GitHub がサポートする形式に従う

## Functional Requirements

1. 「Claude Code への依頼 → view が開く」を収めた mp4 動画を1本制作する (同一素材から README 向けと X 向けの書き出しを分けてよい)
2. 動画は README 冒頭に埋め込み、インライン再生できる
3. 動画は X にアップロードしてインライン再生できる形式とサイズに収める
4. デモの筋書きをリポジトリ内に記録し、撮り直しを可能にする
5. README の動画直下に、インストールコマンドへの導線を置く

## Success Metrics

- X 投稿のインプレッションと動画再生数、投稿後の GitHub リポジトリへの流入 (referrer) が観測できる
- 公開時点の GitHub Releases 累計ダウンロード数を記録し、公開前7日間と公開後7日間の増分を比較して、公開後が上回る
- 初見の開発者3名に動画だけを見せ、2名以上からプロダクトの説明が一言で返ってくる
