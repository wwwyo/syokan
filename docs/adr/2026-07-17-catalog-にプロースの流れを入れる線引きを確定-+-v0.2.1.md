# catalog に「プロースの流れ」を入れる線引きを確定 + v0.2.1

- Status: Accepted
- Date: 2026-07-17

[#34](https://github.com/wwwyo/syokan/pull/34) merged（プロース専用の制限付き `Markdown` node）。/rss の daily feed が Text 羅列 + Stack gap-8 で読めなかったのが発端だが、markdown を入力パスに戻すと [#25](https://github.com/wwwyo/syokan/pull/25) の判断（第二の表現パスが catalog の表現力不足を隠す）の巻き戻しになる。線引きを **「block 構造とデータは catalog node、プロースの流れは Markdown」** と定め、被る構文（heading / GFM table / task list / raw HTML / image）は運用ルールでなく POST 時 validation で 400 + 置き換え node 指名という機械的排除にした（規約は破られるが validation は破れない）。実データ 28 記事で 193 Text node → 73 node に。同 PR 2nd commit で「削除は breaking なので今しかできない」と全20ノードを棚卸しし、PlainText（Code への純粋 alias＝何も買っていない）と Text.clamp（死んだ prop）を削除、AGENTS.md に **admission bar**（node は interaction/state・validated data semantics・rendering engine・navigation 構造のいずれかを買うこと／alias 禁止／タイポグラフィは Markdown の領分）を明文化 — 追加は非破壊・削除は破壊という非対称性ゆえ、審査は追加時に最大に厳しくするのが正しい位置。[#35](https://github.com/wwwyo/syokan/pull/35) merged（幅変化 reflow で読書位置をピクセルでなく**要素にアンカー**。scrollRestoration は履歴遷移のピクセル復元しか担わず、reflow すると同じ scrollY が別の内容を指すため。window resize でなく content column の ResizeObserver にしたのは、サイドバー開閉が `window.innerWidth` を変えずに本文を reflow するから）。catalog 変更に伴い外部 skill を追従（[wwwyo/me#27](https://github.com/wwwyo/me/pull/27)・[wwwyo/me#28](https://github.com/wwwyo/me/pull/28)・[wwwyo/dotfiles#23](https://github.com/wwwyo/dotfiles/pull/23)）
